Create Sales Order

Build a sixteen-step Test that logs into SAP, opens Manage Sales Orders V2, fills the order header across two screens, adds line items, and captures the sales order number as evidence. The longest of the standard Order-to-Cash Tests.

Steps16
App IDcreateSalesOrder
Dataseto2c-e2e.csv
CapturessoNumber

Before you start

  1. The createSalesOrder objects must exist in the Object Library — the four header fields, continueButton, soldToPartyField, itemsTabButton, createButton, and the two line-item columns.
  2. A dataset must supply orderType, salesOrg, distributionChannel, division, soldToParty, product, quantity, automationReferencePrefix and automationOwner. o2c-e2e.csv already does.
  3. An SAP target must be configured and classified Non-production — this Test creates real documents.

pick choose from the list the field offers type type the value leave already correct — don't touch it

How values work. Click into a value field and it lists everything it can be bound to — dataset columns grouped by file, SAP system values, and anything an earlier step captured. Picking one creates the binding. Typing instead makes it a fixed value. The tag to the left of the box always says which you've got.

Create the Test

  1. Compose Tests → Compose New Test.
  2. Test name: Create Sales Order - Happy Path
  3. Process area: pick Order to Cash, or create it.
  4. Create Test.

Steps 4–7 repeat the same module. Build step 4, then select it and use DUPLICATE for 5, 6 and 7 — the clone opens ready to edit and you only change the two values. It only helps for a consecutive run of the same module, which is what these are.

Save Test. Each step needs its own Save step first — the Test isn't written to disk until you press Save Test and see the "Saved at" confirmation.

After you build it

  1. Check the tags down the steps list. Every value that should come from data should read dataset. A stray literal is the most common authoring mistake.
  2. Publish the Test once its contract is declared.
  3. Chain it — this Test is the first stage of the Order-to-Cash process, feeding Create Outbound Delivery and Create Billing Document. A later stage can bind to soNumber as a prior-step output.
