Tracker governance and update rules
  1. This file is the only backlog whose status and release fields are maintained.
  2. Update an item's delivery state, acceptance progress, status, coverage note, evidence and updated date when implementation changes.
  3. Acceptance criteria may change only through an approved product decision recorded in the change log.
  4. Implemented requires repository evidence and applicable regression coverage; a UI mock-up alone is not build coverage.
  5. Legacy IDs remain searchable for auditability but their Markdown files are historical inputs.
